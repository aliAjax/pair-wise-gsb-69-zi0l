# 数据中心变更窗口与回滚方案审阅平台

面向机房运维、系统、安全和业务负责人的生产变更审阅工作台。工程使用 Angular CLI 独立构建，变更记录与容量台账作为同一快照原子写入浏览器 `localStorage`，首次运行通过 `HttpClient` 加载 `public/mock/change-requests.json` 与 `public/mock/capacity-ledger.json`。

## 技术栈

- Angular 22 + Angular CLI + TypeScript
- Clarity Angular 18 + Clarity UI
- NgRx Store + Effects
- Angular Router + HttpClient
- RxJS

## 功能

- 变更列表搜索，以及按状态、资源类型和风险等级筛选
- 新建变更方案，维护资源、依赖、执行步骤、回滚步骤、值守人员和窗口
- 依赖关系图与共享资源窗口甘特图
- 依赖遗漏、窗口冲突、回滚不可执行、关键服务观察窗口不足校验
- 网络、系统、安全、业务负责人顺序会签
- 执行步骤勾选、实时日志入口、执行偏离记录、完成或回滚判定
- 审批冻结、审计轨迹和复盘 Markdown 导出
- 基于 NgRx 的状态流转与 localStorage 持久化

## 变更计划 × 容量台账 × 顺序会签

- **容量台账**：每个机房维护机柜（U）、网络（Gbps）、服务（实例）容量池，仪表盘实时展示各池占用与预留流水
- **严重变更门禁**：严重（critical）变更在同一机房同一时段最多占 2 项，超出即拒绝提交
- **提交即预留**：提交审批前先预留机柜、网络和服务容量；容量不足时拒绝提交并保留草稿，拒绝原因写入审计轨迹
- **容量随状态流转**：会签退回、执行完成或回滚时自动释放预留；审批中的方案被修改后，旧会签全部失效并自网络负责人重新会签，容量按新方案重新预留

## 多标签页并发与故障恢复

- **乐观锁**：快照携带版本号，保存时比较并交换；两个标签页同时保存时，后到一方加载最新台账并收到版本冲突提示，先行结果不会被覆盖，未写入的修改保留在冲突记录中
- **跨标签页同步**：任一标签页写入后，其他标签页通过 `storage` 事件实时加载最新变更与台账
- **写失败恢复**：写入失败（如存储配额不足）时数据保留在内存中并可一键重试；重开浏览器恢复到最后一次成功写入的快照，容量预留与审批状态不丢失
- **旧数据迁移**：自动为历史快照补齐版本号、容量需求，并为持容量状态的变更补建预留记录

## 运行

```bash
npm install
npm start
```

默认开发地址为 `http://localhost:18469`。

生产构建：

```bash
npm run build
```

构建输出位于 `dist/pair-wise-gsb-69/browser`。

领域规则（容量门禁、会签重置、乐观锁、快照迁移）的 sanity 检查：

```bash
npm run check:rules
```
